# 提示词与工程如何配合

状态：设计与验收清单。提示词包可以在支持 Skills 或文件读取的 Agent 内使用；这不等于本项目已提供持久调度系统。

## 可先用提示词驱动的工作

Chief 读取目标及验收，决定拆分、优先级、角色、合理假设和下一步；使用宿主实际存在的子 session 工具委派，按任务卡交接；读取产物并发起审查；复核未完成事项、总结失败、写待验证记忆。用户仍可随时纠偏。真实表现取决于模型、上下文和宿主，必须通过任务验证。

当前入口是 [Roundtable Work Skill](../.agents/skills/roundtable-work/SKILL.md)，按需加载共享指令和角色说明。也可让支持读取文件的 Agent 明确阅读该入口。宿主没有 session 能力时，不能假装存在独立审查者；可以报告降级，并在用户授权内由单 session 执行能做的工作。单 session 自查不能称为独立审查。

## 哪些需要宿主或工程

| 功能 | 最小要求 | 验证 |
| --- | --- | --- |
| 生命周期 | 创建、取消、观察 session，区分身份、会话和委派 | 启动子任务并查看真实结果 |
| 完成通知与等待 | 完成、失败和用户输入能送给正确 owner；空闲后能唤醒 | 让主会话空闲，再观察通知；不支持时报告 |
| 目标与工单 | 一个状态权威；目标版本、owner、验收、等待条件和证据 | 目标中途变化后检查旧结果版本 |
| 外部事件 | 接收、身份认证、授权判断、去重和关联 | 真实事件、重复事件和无权来源测试 |
| 定时唤醒 | 配置时间、时区、预算、过期及错过策略 | 到时触发、暂停和重启后处理测试 |
| 记忆 | 读取/写入/检索，来源与权限、有效期和删除 | 跨会话重载、冲突与修订测试 |
| 恢复 | 输入持久化、未知副作用对账、恢复或安全停下 | 任务运行中断、重启和重复投递 |
| 授权与隔离 | 权限在工具和宿主强制，账号/工作区受控 | 验证无权动作被真实拒绝 |
| 观测和预算 | 工作、等待、失败、费用、资源与人工介入可区分 | 与实际进程/事件交叉检查 |

## 先做什么

1. 固定一个真实宿主和版本，记录真实 session、通知、持久状态、定时与授权工具；已有能力由宿主负责。
2. 在该宿主执行一个低风险工作：Chief 派发、执行者交付、独立审查打回、返修，然后在目标未完成时继续第二项；保存证据。
3. 主会话空闲后等待完成结果，再测试用户中途修改目标。无法唤醒或处理纠偏即记录失败和具体缺口。
4. 只对经验证的宿主缺口增加最薄适配或代码；先定义权威状态与数据所有权。之后测试重复事件、重启与未知外部副作用。
5. 将记忆、定时任务、外部触发和组织扩缩逐项接入并验收。第二宿主运行同一案例后，才考虑稳定通用接口。

不要因为有角色提示词就声称后台团队可运行，也不要因为单次会话演练通过就声称自动恢复。一个完整 setup 必须指明具体宿主、可执行步骤、诊断和验收。
