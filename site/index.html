Roundtable Work: a synthetic walkthrough

A role-based workflow for agents: a human sets the goal, a Chief coordinates, executors do the work, checks and an independent review follow, and a human decides on the merge.

Synthetic data. Everything in this walkthrough is invented: the people, the fictional Notekeep app, the task, the IDs and the results. It is not taken from any real project, issue, log, diff or machine. It illustrates the documented workflow; it does not show a live system, and it does not promise 24/7 operation or that any failure can be recovered from.

What it is

Roundtable Work is a skill and configuration for existing agent hosts. One Chief owns the goal, the other roles work in separate sessions, and handoffs use a ticket, a delegation card, a delivery card and a checkpoint record. It has no background runtime of its own, and this page is an explanation, not a live system.

How every Chief turn ends

Each turn ends with exactly one continuation decision.

continue
Do the next step now, in this turn.
wait
Wait for a named event and say how the wake-up would happen. Other independent work can go on.
ask
A human decision is needed for one item. Only that item is suspended.
done
Every acceptance item has evidence.
stop
The budget is spent, there is no progress, the risk is too high or authorization is gone.

The flow at a glance

Text first: nine stages, in order.

  1. Human goal
  2. Chief
  3. Developer
  4. Test gate
  5. Scope gate
  6. Independent reviewer
  7. Chief commit
  8. Pull request
  9. Human merge (outside the demo)

Checks before review are called the test gate and the scope gate in this demo. They are instructions that an agent follows, not an automated enforcement engine. Independent review means a separate session judges the delivery. Its verdict line is 审查结论：通过 | 打回 | 阻塞 (approved | rejected | blocked).

Roles

A role is not a model. A separate session gives a fresh viewpoint, but a different model or name is not proof of quality.

  • Sample Requester

    Role: human

    Sets the goal, the acceptance and the limits. Can correct, pause or stop at any time. Merging is a human decision.

  • Chief (demo)

    Role: chief

    The main contact. Writes the ticket, splits and delegates the work, reads the results, and ends every turn with one decision.

  • Researcher (demo)

    Role: researcher

    Answers a bounded question with sources and separates what was observed from what was inferred.

  • Developer (demo)

    Role: developer

    Turns a delegated task into a verifiable artifact and reports in a delivery card. Does not commit by default.

  • Independent Reviewer (demo)

    Role: reviewer

    Judges the delivery against the original goal and acceptance, in a session separate from the author’s.

    The first line of its card is the verdict: 审查结论：通过 | 打回 | 阻塞 (approved | rejected | blocked).

  • Fixer (demo)

    Role: fixer

    Handles a delegated bug: reproduces it with a failing check first, then fixes it.

Rejection, fix and approval

✕ Sent back or stopped

The reviewer sends the work back, the original author fixes it, and a second review passes. The verdict line is shown exactly as the reviewer writes it.

  • Step 11: The original author fixes the findings (state working).
  • Step 14: Independent review: approved (state ready). Verdict line: 审查结论：通过 (approved).

◐ Waiting or asking

When things go wrong

These branches show what the Chief does. They never say that recovery will succeed.

Pause controls

The first five entries are real controls described by the repository instructions. The last one is a visual control on this page only.

Human pauses, corrects or stops
The human can send a correction, pause or stop at any time. Chief handles the correction before new work. Whether a sub-session that is already running can be interrupted depends on the host.
wait
Chief names the specific event it is waiting for and how it would be woken. Unrelated work can continue. It is not a promise that a wake-up will happen.
ask
Only the item that needs a human decision is suspended, with a concrete question and a recommendation. Other work continues.
stop
Used when the budget is spent, no progress is made, risk exceeds the limit or authorization is lost. Chief stops the related attempts and reports the reason and the needed decision.
Human merge
Merge and deploy always need a human decision under the default policy. The demo itself has no merge button.
Demo playback pause ◐ Visual control only
A visual control on this page that pauses or steps its animation. It changes nothing outside the page and does not stand for any real system control.

Limits

  • This is a synthetic walkthrough, not a recording of a real run.
  • Roundtable Work is a skill and configuration for existing agent hosts. It has no background runtime of its own, and the demo makes no claim of 24/7 operation.
  • A turn ending is not a wake-up. Resuming without a person depends on host features that have not been verified here.
  • Nothing here promises that any failure can be recovered from; some work will stop and need a person.
  • Independent review reduces shared blind spots but is not proof of correctness.
  • Test and scope gates are Chief verification steps described in instructions and performed by an agent; they are not automatically enforced by a runtime.
  • The demo performs no merge, deploy or other privileged action. Merging is a human decision outside the demo.
  • The default budgets are template defaults that a deployment may change.
