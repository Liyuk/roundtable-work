# Operating Policy

> Generated by setup and maintained by the deployer. Can only narrow harness permissions here, not expand them. Write credential references only, never secrets.

## Authorization

- Can accept work from (user, specific issue labels, CI events...): the user themselves
- Can execute without confirmation: read workspace; modify code in feature branch or isolated working tree; commit locally to feature branch after review passes; run local tests and checks
- Must ask user first: merge to main branch, release or deploy, send external messages or comments, delete data, install global dependencies or third-party skills
- Forbidden: <deployer fill in>

## Budget and Stop Conditions

- Maximum attempts per assignment: 2
- Review rejection maximum: 2 rounds, after which escalate to user judgment
- Consecutive no-progress round limit: 2 (no new facts, no new artifacts count as no progress) → `stop`
- Concurrent writers to same file: 1
- Single goal time or cost limit: <not set>

## Execution Routing

| Work Type | Execution Method | Model Tier | Verified |
| --- | --- | --- | --- |
| Implement / Fix | Harness sub-session | From routing table | Not verified |
| Independent Review | Another harness sub-session | From routing table | Not verified |

"Verified" only changes to date and evidence location after actually running through once.

Role-to-model routing comes from the single active routing table; this policy neither sets nor bans individual model names. A model listed in the injected routing facts block is expected and allowed; an unlisted model is a configuration error to record, not a reason to stop.

## Triggering and Wake-up

- User message: Enabled
- Sub-task completion notification: <harness support, detected by setup and filled in>
- External events (GitHub, CI, webhook): Not enabled
- Periodic health check: Not enabled (when enabled, specify purpose, timezone, interval, validity period, budget and stop conditions)

## Notification and Records

- When user decision needed or delivery due: report in current conversation
- Ticket and continuation record location: `.roundtable/tickets/`, `.roundtable/state/` (if harness has task system, reference harness instead)
- Memory location: `.roundtable/memory/`; do not write sensitive content to committable files
